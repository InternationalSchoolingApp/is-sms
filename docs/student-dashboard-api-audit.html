Kya mila (findings)

  • 1. Maintenance check sabse aage queue mein hai. Next.js server actions ek page pe ek-ek karke chalte hain. getMaintenanceDowntimeStatus (MaintenanceBanner, har 60s) ek server action hai aur Tier 1 se pehle chalta hai. Jab ye dheema hua (21.6s), poora dashboard utni der ruka. Idea: ise /api/... route handler bana do (jaise /api/diary), taaki ye queue mein na baithe.
  • 2. Backend parallel load mein dheema ho jaata hai. Wahi 12 Tier 1 calls Run 1 mein 8–11s aur Run 2 mein 2–7.5s; akeli chhoti calls (get-setting, links) 0.1–0.4s. Ye DB pool ki kami jaisa lagta hai — dev config mein read pool max 3 aur write pool max 8 hai, aur aaj backend log mein APIWritePool - Connection is not available bhi aaya tha.
  • 3. Chhoda hua request backend ko pakde rehta hai. Page reload ke baad bhi pichhle page ki student-academic-performance 46.5s tak chalti rahi aur connection ghere rahi.
  • 4. Sabse dheemi APIs: school-calendar 7.5s, get-student-dashboard 6.2s (Run 2 mein dobara 9.9s), additinal-layer-details 5.2s, get-user-short-profile 5.2s, dashboard-or-migration 4.6s, student-academic-performance 4.5s.
  • 5. Chain: sidebar menu (module-details) aur My Performance (student-academic-performance) get-student-dashboard ke jawab ka intezar karte hain (roleId / k5 flag). Isliye Tier 1 ≈ 6.2s + 4.5s.
  • 6. Duplicate calls (ek hi load mein): dashboard-or-migration ×2 (Tier 1 + system training) · additinal-layer-details ×2 (onboarding + Outlook) · get-student-dashboard ×2 (Tier 1 + baad mein 9.9s) · get-setting ×7 (alag keys, alag calls). Tier 3 Tier 1 ke jawab dobara use kar sakta hai.
  • 7. Jo theek hai: Tier 2 aur diary tez hain (≤1s); Tier 1 ke andar calls sach mein saath-saath chal rahi hain (Promise.all); 39 → 5 server actions wali batching kaam kar rahi hai.

Ye audit hai — maine koi fix nahi lagaya. Upar ke ideas pe kaam karna ho to bataiye.
