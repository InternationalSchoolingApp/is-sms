Response — naye fields

  courseProviderId, lmsUserId, userName,
  studentAcademicPerformances: [ { ...existing fields...,
      "classComparison": {                // null jab class chhoti ho / comparison off / data na ho
        "size": 24,                       // classmates + student
        "avgScore": 81.5,  "avgProgress": 12.3,

        "youOnTime": 100,  "classOnTime": 72,   // % on-time submissions
        "onTimePct": 70,

      } } ],
  "k5Goals": { "score": 85, "finishBy": "2027-06-20", "remind": "Y", "compare": "Y", "saved": true }
}

Classmates kaun? (SQL)

  • Same LMS course: BUZZ_ENROLLMENT.ENTITY_ID = course.lmsCourseId
  • Active: LMS_USER.ACTIVE='Y' AND DELETED='N' (join on LMS_USER_ID)
  • Progress: BUZZ_GRADES join ENROLLMENT_ID = BUZZ_ENROLLMENT.ID → COMPLETED / COMPLETABLE
  • Score: BUZZ_ENROLLMENT.ACHIEVED / POSSIBLE
  • On-time: BUZZ_ACTIVITY per LMS_USER_ID — submitted items mein SUBMITTED_DATE <= DUE_DATE, excused chhod ke
-- BuzzEnrollmentDao (native, ek query per course)
SELECT e.LMS_USER_ID, e.ACHIEVED, e.POSSIBLE, g.COMPLETED, g.COMPLETABLE
FROM BUZZ_ENROLLMENT e
JOIN BUZZ_GRADES g ON g.ENROLLMENT_ID = e.ID
JOIN LMS_USER lu ON lu.LMS_USER_ID = e.LMS_USER_ID AND lu.ACTIVE = 'Y' AND lu.DELETED = 'N'
WHERE e.ENTITY_ID = ?1

-- BuzzActivityDao (on-time per student in that course)
SELECT a.LMS_USER_ID,
       SUM(CASE WHEN a.SUBMITTED_DATE <= a.DUE_DATE THEN 1 ELSE 0 END) AS ON_TIME,
       COUNT(*) AS SUBMITTED
FROM BUZZ_ACTIVITY a
WHERE a.ENTITY_ID = ?1 AND a.SUBMITTED_DATE IS NOT NULL AND (a.EXCUSED IS NULL OR a.EXCUSED = 0)
GROUP BY a.LMS_USER_ID

Java mein: averages, percentile (kitne classmates ka value student se kam hai, ties half), 8 bands. Student ka apna score/progress live LMS wala use hoga (jo page pe dikhta hai), classmates ka DB snapshot.

Kab null bhejenge

  • Flag nahi bheja
  • Student ne comparison off kiya (K5_GOAL_COMPARE = N) — server pe bhi check, sirf UI pe nahi
  • Class size < 5 (privacy, neeche dekho)
  • Non-Buzz provider (36/37/38 ke alawa)

6. Risks / decisions (maine ye defaults liye hain)

Privacy — minimum class size 5: mockup MIN_CLASS = 2 leta hai, lekin 2 students mein class average se doosre student ka exact score nikal aata hai. Isliye 5 rakha hai. Chahiye toh constant badal sakte hain.
Data freshness: classmates ka data scheduler ke last run jitna purana hoga (frequency abhi confirm nahi). Student ka apna data live rahega.
Classmates scope: "same LMS course (ENTITY_ID)" — matlab us course ke saare active Buzz students, chahe section/teacher alag ho. Same teacher/section tak limit karna ho toh STUDENT_SESSION_SUBJECTS join add karna padega (abhi verify nahi kiya).
Existing security gap (purana, chhua nahi): student-academic-performance student session mein studentUserId payload se leta hai aur check nahi karta ki wahi login student hai. Naye fields bhi isi response mein jayenge — alag se fix karna chahiye.
