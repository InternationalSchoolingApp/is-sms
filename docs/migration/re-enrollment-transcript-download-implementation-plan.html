1. Summary & decisions

Re-enrollment option screen pe har eligible student ke liye (saare grades, pass + fail) option rows ke neeche "Download your transcript" card. Grade 12 pass pe diploma bhi. Download blocked ho toh button disabled + saare reasons + har reason ka fix isi page pe (school hold ko chhod ke — wo sirf school hata sakta hai).

8. Phase 2 — Documents inline upload

Goal: koi MISSING doc ho toh card ke andar hi upload; upload hote hi doc done (D7) aur saare 3 uploaded hone pe docs blocker hat jaaye. Profile pe redirect nahi.

Existing profile upload reuse (naya backend nahi)

  • FE chain: hooks/useProfileActions.js → multipart POST /api/profile/document → app/api/profile/document/route.js (file → data URL) → BE dashboard/save-docs.
  • BE body: { userId, studentStandardId, documentUploads: [{ filePath: "data:…;base64,…", fileName, docType, imgID: "" }] }.
  • BE ClientDashboardCommonController ~2503 → UploadDocsUtil.uploadProfileDocs: naya ATTACHMENTS row (ACTIVE=Y), purana same-type row deactivate. Yahi table admin getMissingAcademicDocsByUser padhta hai → doc turant UPLOADED.
  • docType: Age Proof → "Age Proof", Parent Passport → "Signature", Last academic proof → "Last Academic Proof" (services/profileFacts.js, components/k5/pages/K5ProfileDocs.jsx jaisa).

9. Phase 3 — Removed (fee / Pay now)

D21: payment card se hata di gayi. Kyun: jis student ki fee 7 din se zyada overdue hai use app ka onboarding gate (useOnboardingGate) /student/welcome pe rok leta hai, jahan "Pending Fee … Pay Now" modal pehle se hai (wahi useCartCheckout). Additional-layer API (dashboard/additinal-layer-details) fee rows sirf us 7+ din wale case mein deti hai, baaki students ke liye kuch nahi. Isliye card mein fee blocker / Pay now / checkout nahi hai; card sirf school hold + documents dikhata hai.

10. Phase 4 — Enforcement (flag ke peeche, same release)

  • TRANSCRIPT_BLOCK_ENFORCE_ALL=Y hone pe hi: studentTranscriptStatus (My Transcript), parent student-academic-details (DashboardParentUtil ~925-975), mobile — current grade ke transcript pe same rule (shared service method). Purane grades block nahi. Admin / teacher kabhi block nahi.
  • FE: Transcript.jsx / K5Transcript.jsx link ki jagah reason text (same mapper).
  • Public routes (PublicRoutes.java: transcript-oddy, view-diploma, verification, QR) block nahi — PDF generator / QR ke liye.
  • Release mein flag N; ON karne se pehle mobile team ko batana.

Later — not in this release (user: "ye kaam baad krenge")

Abhi upload = done. School verification baad mein. Ye list memory mein saved hai; "re-enrollment ka konsa kaam bacha hai" poochne pe yahi batana:
  • Uploaded docs school verify kare tab unlock (UNDER_VERIFICATION / REUPLOAD with remark).
  • Profile save-docs sirf ATTACHMENTS likhta hai → verify nahi ho sakta; ek shared util se pending STUDENT_ENROLLMENT_DOCUMENTS row (profile upload + card upload dono) — decided "same shared util".
  • Purane uploads ke liye SED backfill (pending vs verified decide karna).
  • School ko pata chale: admin Student Transcript docs rail mein "Under verification" state + filter.
  • SED row ka STANDARD_ID scoping taaki signup docs gate (SignupStudentUtil ~1476) affect na ho.
