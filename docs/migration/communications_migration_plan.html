Communications (Inbox): migration from JSP to Next.js

Moves the legacy Inbox page (emails, notifications, announcements, WhatsApp, Sent, Compose and Reply) from is-rest-api (jQuery page) into is-sms (Next 16, React Query, Tailwind v4, shadcn ui). Only existing backend endpoints are used.
Branch feature/version_1_3_0_phase4 Sidebar pageLink inbox (+ inbox-compose) Status Plan: no app code changed Written 2026-11-12

1 Summary

The legacy Inbox is already well built on the server: InboxController ({schoolId}/dashboard/inbox/*) always works on the token user (InboxService.viewer() → CurrentIdentity.getUser), checks the module right inbox, and checks every id again (email, attachment, reply, recipients). So the migration is mostly a front-end rewrite plus three small Next.js route handlers for the parts a Server Action cannot carry (multipart send, the sandboxed email body, and attachment downloads).

5 Security review

Already safe in the legacy backend (keep as is)
  • No user id is read from the payload: every endpoint uses InboxService.viewer() (token user) and checks the inbox module right.
  • childUserId is checked against the viewer's own children; email, attachment, star and reply ids are checked against what the viewer may see.
  • Send checks every recipient again on the server, the daily cap, subject/message length, file count, size, extension and file signature.
  • The email body is served with Content-Security-Policy: sandbox …; script-src 'none' and shown in an iframe without allow-scripts.
#Gap / riskFix in the migrationWhere
S1The browser in is-sms has no backend token cookie, and we must not forward cookies. The legacy page opens email-content and attachment straight from the browser.Proxy both through Next route handlers that add Authorization: Bearer from getAccountSession(). Only the opaque payload is taken from the browser; school comes from the session.app/api/inbox/*

S3Announcement attachments are public S3 links (FILE_UPLOAD_PATH + name): anyone with the file name can open them, no access check.Phase 1: keep parity using utils/announcementAttachment.js (same as the K5 announcements panel). Logged as a backend follow-up: serve them through an existing checked endpoint. question Q4reader
S4Server Action body limit is 1 MB by default; three 5 MB files would fail or tempt someone to raise the limit for all actions.Send through POST /api/inbox/send (route handler, same pattern as app/api/profile/document). 8 Attachment download example

Today the legacy reader links each attachment to /dashboard/inbox/attachment?payload=… in a new tab; the backend checks the viewer again and answers 302 to a 5-minute S3 link. In is-sms the browser has no backend token, so the Next server does the call and streams the file back with a real file name.

8.1 Route handler (server)

// app/api/inbox/attachment/route.js  (planned)
import { NextResponse } from "next/server";
import { getAccountSession, serviceKeyHeaders } from "@/lib/auth/session";
import { hasBackendOrigin, resolveServerBackendOrigin } from "@/utils/backendOrigin";

const S3_HOSTS = (process.env.INBOX_ATTACHMENT_HOSTS || "s3.amazonaws.com").split(",");
const plain = (status, message) => NextResponse.json({ message }, { status });

export async function GET(request) {
  const me = await getAccountSession();
  if (!me?.accessToken || !me?.schoolUUID) return plain(401, "Your session has been logged out");
  if (!hasBackendOrigin()) return plain(500, "The backend is not configured.");
  const payload = request.nextUrl.searchParams.get("payload");   // opaque, from the email answer
  if (!payload) return plain(400, "The attachment link is missing.");

  const base = await resolveServerBackendOrigin();
  const check = await fetch(
    `${base}/${me.schoolUUID}/dashboard/inbox/attachment?payload=${encodeURIComponent(payload)}`,
    { headers: { ...serviceKeyHeaders(), Authorization: `Bearer ${me.accessToken}` },
      redirect: "manual", cache: "no-store" });

  if (check.status !== 302) {                    // 403 / 400 / 503: backend text is safe to show
    return plain(check.status === 401 ? 401 : check.status, await check.text());
  }
  const link = new URL(check.headers.get("location") || "", "https://invalid");
  if (link.protocol !== "https:" || !S3_HOSTS.some((h) => link.hostname.endsWith(h))) {
    return plain(502, "This attachment cannot be opened just now.");
  }
  const file = await fetch(link, { cache: "no-store" });
  if (!file.ok || !file.body) return plain(502, "This attachment cannot be opened just now.");

  // Stored names look like "123456789_homework.pdf": show the part after the 9-digit prefix.
  const stored = link.pathname.split("/").pop() || "attachment";
  const shown = decodeURIComponent(stored).replace(/^[0-9]{9}_/, "");
  const headers = new Headers({
    "Content-Type": file.headers.get("content-type") || "application/octet-stream",
    "Content-Disposition": `attachment; filename*=UTF-8''${encodeURIComponent(shown)}`,
    "Cache-Control": "no-store",
    "X-Content-Type-Options": "nosniff",
  });
  const length = file.headers.get("content-length");
  if (length) headers.set("Content-Length", length);
  return new NextResponse(file.body, { status: 200, headers });  // streamed, not buffered
}

8.2 Client side (hook + button)

// utils/inbox.js (planned)
export async function downloadInboxAttachment(attachment) {
  const response = await fetch(`/api/inbox/attachment?payload=${encodeURIComponent(attachment.payload)}`);
  if (response.status === 401) { markSessionExpired(); throw new SessionExpiredError(); }
  if (!response.ok) throw new Error((await response.json().catch(() => ({}))).message
                                    || "This attachment cannot be opened just now.");
  const blob = await response.blob();
  const url = URL.createObjectURL(blob);
  const a = Object.assign(document.createElement("a"), {
    href: url, download: attachment.name.replace(/^[0-9]{9}_/, ""),
  });
  document.body.appendChild(a); a.click(); a.remove();
  setTimeout(() => URL.revokeObjectURL(url), 1000);
}

</Button>
