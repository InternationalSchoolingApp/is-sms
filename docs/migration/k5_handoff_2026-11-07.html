4. Architecture (auth + API pattern)

Token auth (no next-auth)

  • Server user: getAccountSession() (lib/auth/session.js) → {uniqueId, userId, schoolUUID, schoolNumericId, schoolName, email, role, accessToken}. No roleId (roleId dashboard details se aata hai).
  • Java calls: Authorization: Bearer + service key. Client: useSession from components/providers/AuthSessionProvider.
  • proxy.js matcher /:school/student/:path* — isliye API routes /api/student/... me mat banao (school = "api" ban jaata hai). Use /api/profile/....
  • Backend: stateless JWT, SessionUtil → CurrentIdentity, default-deny, UserAccessGuard (Batch A).

Central API pattern

  • utils/backendRequest.js → {ok,data} / {ok:false,code,message,sessionExpired}. Options: buildBody(me), headers(me) (e.g. UNIQUEUUID), checkSession. Identity has uniqueId.
  • Client gate utils/serverCall.js callServer(); global expired dialog components/providers/SessionExpiredDialog.jsx.
  • Payload envelope {payload: btoa(encodeURI(json))}.
  • K5 pattern: existing component keeps logic, returns components/k5/pages/K5*.jsx when isK5. Pages call usePicoContentReady; Pico tips in PicoGuide.jsx PAGE_TIPS.
