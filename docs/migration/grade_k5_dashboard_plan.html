Grade K–5 Student Dashboard — Implementation Plan

Chhote bacchon (Kindergarten se Grade 5) ke liye "Playful" dashboard ka plan, jo existing Next.js student dashboard ke andar hi plug hoga. Ye sirf plan hai, abhi koi code nahi likha gaya.
Frontend: is-sms · feature/version_1_3_0_phase4 Backend: is-rest-api Design ref: D:\Workspace\K-5 dashboard\Playful.dc.html Appearance ref: IS-SMS-Dashboard-Appearance-Plan (1).html Date: 2 Nov 2026 (appearance review ke saath updated)

01 TL;DR

Same URLs
Naya route nahi. /{school}/student pe hi grade dekh ke K–5 shell + home render hoga.
1 DTO
Backend me sirf existing get-student-dashboard DTO me gradeBand + currentGrade add karna hai.
Data ready
Calendar, announcements, news, diary aur chat ka data aur hooks pehle se hain. Bas K–5 UI banana hai.
3 gaps
Weather, homework markers aur stars/rewards ka backend data abhi exist nahi karta. Inko Later ya static rakhna padega.
Short me approach
  1. Backend: GradeBandUtil pehle se bana hua hai, lekin config missing hone ki wajah se sab students ko MIDDLE deta hai. Isko configure karo, aur StudentDetailsDTO me gradeBand expose karo.
  2. Context: useDashboardContext me gradeBand add karo ("ELEMENTARY" | "MIDDLE" | "HIGH").
  3. Layout level: DashboardChrome ELEMENTARY band pe K5Shell render kare: kid header, 96px icon sidebar, right rail aur scoped .theme-k5 tokens.
  4. Page level: student/page.jsx ELEMENTARY band pe StudentHomeK5 render kare (Day/Week/Month planner + Pico guide). Baaki module pages shared rahenge, sirf naye theme me dikhenge.
  5. Preview: ?dummyStudent=Y&dummyGrade=K se backend change ke bina hi UI build aur test ho sakta hai.
  6. Final decisions (section 16): sabhi 7 learning programs incl. CWS (sirf Self-Study nahi), per-school feature flag se pilot, PreK bhi included, MVP = Phase 0–2 (Pico baad me), default Light mode, aur sirf Tailwind CSS (Bootstrap nahi).

6.1 Learning programs: K–5 dashboard sabhi 7 programs ke liye (decision 10)

Ye plan sirf Self-Study ke liye nahi hai K–5 dashboard ELEMENTARY band ke har student ko milega, chahe uska learning program koi bhi ho: BATCH, CWS, DUAL_DIPLOMA, ONE_TO_ONE, ONE_TO_ONE_FLEX, SCHOLARSHIP, SSP. isSelfStudy K–5 ka gate nahi hai.
  • Backend me pehle se aisa hi hai: legacy ClientDashboardStudentController.java:345-347 me gradeBand aur isSelfStudy alag-alag set hote hain, aur DashboardHeaderResourcePage.jsp:156 elementary assets sirf gradeBand=='ELEMENTARY' pe load karta hai, LP pe nahi. Naam "Self-Study revamp" hai, lekin band logic LP-independent hai.
  • isSelfStudy ka kaam: GradeBandUtil.isSelfStudy() sirf SCHOLARSHIP aur SSP ke liye true deta hai, aur filterModulesForSelfStudy se sidebar modules filter hote hain (line 390). K–5 me bhi ye sirf content ka difference hai (menu items, planner ka content), dashboard on/off ka nahi.
  • Gate rule: isK5 = gradeBand === "ELEMENTARY" && k5DashboardEnabled && K5_LEARNING_PROGRAMS.includes(registrationType). Allowlist constant/appearance.js ya utils/gradeBand.js me rahegi. registrationType pehle se StudentDetailsDTO me aata hai.

07 Grade detection flow

// hooks/useDashboardContext.js (proposed)
gradeBand: dummy.enabled
  ? (dummy.student.isElementary ? "ELEMENTARY" : "MIDDLE")
  : details?.gradeBand ?? bandFromStandardId(details?.standardId) ?? "MIDDLE",
isSelfStudy: details?.isSelfStudy ?? false,          // sirf content, gate nahi
isK5: gradeBand === "ELEMENTARY"
  && details?.k5DashboardEnabled                       // decision 03
  && K5_LEARNING_PROGRAMS.includes(details?.registrationType), // decision 10: 7 LPs (sabhi)
// K5_LEARNING_PROGRAMS = ["BATCH","CWS","DUAL_DIPLOMA","ONE_TO_ONE","ONE_TO_ONE_FLEX","SCHOLARSHIP","SSP"]
Fallback rule Agar band unknown ho to MIDDLE (existing dashboard) dikhao. Ye backend ke default jaisa hi hai. Galti se bade bacche ko kid UI dikhana zyada bura hai.

12 Appearance & personalization (Appearance Plan review)

Source: IS-SMS-Dashboard-Appearance-Plan (1).html. Ye doc ek ~12 sec ki recording par based hai jisme sirf personalization panel dikhta hai, dashboard nahi. Iske options mockup ke "Make it yours!" dialog se match karte hain, isliye K–5 plan me isko merge kiya gaya hai. Neeche likha hai ki doc se kya as-is liya, kya codebase ke hisaab se badla, aur kya abhi rakha nahi.

12.1 Doc se kya liya (as-is)

  • Ek central provider: AppearanceProvider + useAppearance() (preferences, isLoading, isSaving, error, updatePreference, resetPreferences). Har page apna alag theme logic nahi banayega.
  • Do layer policy: school/admin defaults + user overrides. Customization OFF hone par user overrides delete nahi honge, sirf inactive rahenge.
  • Interaction: instant preview, auto-save + "Saved" indicator, Reset pe confirmation, failure pe retry. Galat "Saved" message kabhi nahi dikhana.
  • Guardrails: school logo/brand user preference se override nahi hoga. Accessibility options kisi grade se hide nahi honge. Status sirf colour se nahi dikhega, saath me icon/label bhi hoga. Reduced motion respect karna hai.
  • Buddy/voice rule: non-functional controls ship nahi karne. K–5 me Pico + TTS real feature hai, isliye wahan buddy/voice controls dikhenge. MIDDLE/HIGH band me nahi.
  • Test cases APP-001…022 + Playwright scenarios. Mapping section 12.7 me hai.

15 Risks & gaps

  • standardId mapping: PreK (17) → ELEMENTARY confirmed hai. Sirf 19 ka band clear nahi hai. userStandard === 8 ka pehle se special meaning hai (dashboardNav.js:121). STANDARD table se verify karna hai.
  • Flash of wrong layout: grade async aata hai. Shell decide hone tak neutral skeleton dikhana hai.
  • Module pages ke hardcoded colours (slate/black) theme follow nahi karenge. Inhe Phase 3 me clean karna hai.
  • DB-driven menu: K–5 me items ka order/hide sirf client-side filter se hoga. Authorization backend hi enforce karega.
  • K–5 calendar rule (max 3 classes/week) abhi sirf dummy data me hai. Real data me backend weekly limit enforce karta hai, isliye UI ko kuch alag nahi karna.
  • Web Speech / WebAudio: iOS Safari pe autoplay restrictions hain. Pehle user gesture ke baad hi audio chalana hai.
  • localStorage keys user-scoped nahi: studentDashboardCalendarNew (existing) aur mockup ke is-k5-look / is-k5-nav shared device pe dusre user ko leak ho sakte hain (APP-014). Naye keys me userId ho.
  • Cross-device persistence ka backend nahi hai: user preference table/endpoint exist nahi karta. Appearance Plan ke APP-005 aur "Reset all users" isi pe depend karte hain.
  • Child privacy: weather/location ya koi third-party call bina review ke nahi karni.
  • Legacy elementary JSP assets (self-study-elementary.css, elementaryHome.js) bhi same band use karte hain. Config on karte hi legacy dashboard bhi badal jaayega. Ye coordinate karna padega (ya toggle ke peeche rakhna).
