P0 Backend check koi app code nahi

Goal: pakka karna ki legacy endpoints Next server se chalengeDepends on: —

Kaam

  1. Test student se login (:8080 SSO, test student IDs) karke Next server se ek temporary script chalao jo backendRequest jaisa Bearer header bheje.
  2. Har JSON endpoint call karo: list, children, unread, email, notification, announcement, star, mark-all-read, compose/contacts, compose/reply, sent, email-settings. Sab status "1" dein.
  3. Dono GET check karo: email-content?payload= HTML aur CSP header deta hai; attachment?payload= 302 deta hai (fetch me redirect: "manual").
  4. Multipart compose/send ek test teacher ko 1 chhoti file ke saath bhejo (sirf dev / UAT par).
  5. Confirm karo: student role ke paas inbox right hai, sidebar menu me pageLink inbox (aur inbox-compose) aata hai.
  6. Har environment ka S3 host note karo (attachment redirect kahan jaata hai) → INBOX_ATTACHMENT_HOSTS env value.
  7. Temporary script delete karo.

Done kab

Saare endpoints test student ke liye kaam karte hain aur S3 host list tay hai. Koi endpoint fail ho to yahin ruk ke backend issue note karo.

P3 Reader + attachment download

Goal: har item kholna, email body safe dikhana, attachment downloadDepends on: P2

Nayi / badli files

FileIs phase me kya
components/student/inbox/InboxReader.jsxshadcn Dialog (mobile par Sheet). Views: Email (sender, time, child chip, undelivered notice, attachments, iframe body, Print), Notification (text), Announcement (text, attachment, "I have read this"), WhatsApp (sirf naam + note, list ke data se).
app/api/inbox/email-content/route.jsGET ?payload=: session se Bearer, backend email-content call, HTML wapas; backend ka CSP header copy, X-Content-Type-Options: nosniff, Cache-Control: no-store.
app/api/inbox/attachment/route.jsGET ?payload=: redirect: "manual", 302 ka Location sirf https: + INBOX_ATTACHMENT_HOSTS par maano, file stream karo Content-Disposition: attachment aur readable naam ke saath (9-digit prefix hata ke). 403/400/503 ka backend text wapas.
services/inboxApi.js+ openInboxEmail(id), openInboxNotification(id), openInboxAnnouncement(id, childUserId), acknowledgeInboxAnnouncement(id, childUserId).
hooks/useInbox.js+ useInboxItem(channel, id) (success par list + unread invalidate), useAcknowledge.
utils/inbox.js+ downloadInboxAttachment(a) (fetch → blob → <a download>, 401 par session-expired), shownAttachmentName(name).

Endpoints

email, notification, announcement, acknowledge, GET email-content, GET attachment

Kaam

  1. Row click → reader khule, andar skeleton, phir detail.
  2. Email body: <iframe sandbox="allow-same-origin allow-popups" src="/api/inbox/email-content?payload=…">; load par height adjust (200–3000 px), legacy jaisa.
  3. Attachment button: "Preparing…" state, error toast, readable naam se save.
  4. Announcement attachment: abhi getAttachmentUrl (utils/announcementAttachment.js) se naye tab me (Q4 ka jawab aane tak).
  5. "I have read this" → acknowledge → confirmation text.
  6. Print: sirf reader ka content (print CSS).
  7. Reply button abhi sirf dikhe jab canReply true ho; click P4 me jodenge.

Security

  • S1: dono GET Next se proxy, browser ko backend token / URL nahi.
  • S2: dangerouslySetInnerHTML kabhi nahi; iframe me allow-scripts nahi.
  • S6: non-S3 redirect par 502.

Tests

IN-09 se IN-13, SE-02, SE-03.

Done kab

Har channel ka item khulta hai, read status aur badge update hote hain, attachment sahi naam se download hota hai, aur tamper kiya payload 403 deta hai.

Nayi / badli files

FileIs phase me kya
app/api/inbox/send/route.jsPOST multipart (to[], subject, message, inReplyToId, files). Checks: to khaali nahi, subject 1–200, message 1–10,000, max 3 files, har ek ≤5 MB, extension list (pdf, jpg, jpeg, png, gif, doc, docx, xls, xlsx, ppt, pptx, txt, csv). Phir encodePayload ke saath multipart Bearer se backend compose/send ko. Answer: backend data ya {message} (400 / 401 / 502).

utils/inbox.js+ FILE_RULES, fileProblem(files) (backend jaise messages).
components/student/inbox/Inbox.jsx, InboxReader.jsx"Write a message" button (sirf canCompose true par), Reader ka Reply → getReplyDraft → Compose (To + "Re: …" bhara hua).

Endpoints

compose/contacts, compose/reply, compose/send (multipart)

Kaam

  1. enabled false ya canCompose false → button hidden; reason text compose route par dikhe.
  2. Send success → toast me backend message, dialog band, draft reset.
  3. Background send (background: true) ka message bhi waisa hi dikhe.
  4. skipped list ho to toast / dialog me naam aur reason.
  5. Network error ya refusal → inline error, form bhara rahe.
  6. Reply: To lock (ek hi teacher), subject "Re: …", inReplyToId bheja jaaye.

Security

  • S4: files route handler se, Server Action limit nahi badhani.
  • Recipients sirf ids; backend har id dobara check karta hai. Client se koi sender id nahi.
  • S8: session expire par draft bana rahe.

Tests

Done kab

Student teacher ko 2 attachments ke saath message bhej sakta hai, teacher ke message ka reply kar sakta hai, galat input par legacy jaise messages aate hain.
