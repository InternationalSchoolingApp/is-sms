2. Rules to follow

  • Do not commit or push without the project owner's approval. Build, check, show, then wait.
  • Use the existing backend endpoints. The Inbox was built with no is-rest-api change. Where a gap needs a backend field (see the Transcript row), raise it first.
  • Next.js 16 is not the version most references describe. Read the guide in node_modules/next/dist/docs/ before writing Next-specific code (AGENTS.md).
  • Time zones: use the user's own zone; when it is missing or invalid fall back to Asia/Singapore; never overwrite a valid configured zone (AGENTS.md).
  • Images: prefer next/image; never switch off the image lint rule globally (CLAUDE.md).
  • After changing code run graphify update . so the knowledge graph in graphify-out/ stays current (CLAUDE.md).
  • Wording: clear messages a student can act on, not "invalid request" or "refresh your browser". The school name always comes from the session, never hard-coded.
  • Real data: anything that sends a message, email or payment, or changes an account, is done only on a test student and only after the owner agrees.
  • From the 2026-11-07 handoff, still in force: use components/ui/date-picker.jsx instead of a native date input, and use the look's accent colour (var(--k5-ac)) for selected and active states.

3. How the dashboard is built

One page, two shells

  • Every page is a route app/[school]/(dashboard)/student/<page link>/page.jsx that renders components/student/X.jsx. That component holds the old-shell version and switches to components/k5/pages/K5X.jsx when useDashboardContext().isK5 is true.
  • The page link is the same string the backend menu uses (fee-details, student-attendance-overview, …). A menu item with no route falls to student/[...module]/page.jsx, which shows "This module is being migrated and will be available soon (Phase C)."

Three grade looks from one component tree

  • Playful (K–5), Balanced (6–8) and Mature (9–12) are the same components/k5/* components. The look is only attributes on the .theme-k5 root from useK5ThemeProps(): nothing for Playful, data-k5-band="middle" for Balanced (app/k5-middle.css), plus data-k5-high for Mature (app/k5-mature.css).
  • The Balanced and Mature skins restyle by matching the exact Tailwind arbitrary class spellings used in the K5 components (border-[3px], rounded-[26px], text-[16px], min-h-[48px] …). A new component is skinned for free only if it uses those same spellings; anything else needs its own rule in the two skin files.
  • A dialog rendered outside the shell must spread the same theme props, or it loses the look.
  • useDashboardContext() gives isK5, isMiddle, isHigh, isPreK, the menu and the session facts.

Talking to the backend

  • Calls go through a "use server" file in services/ built on utils/backendRequest.js. File uploads and downloads go through a route handler under app/api/.
  • The backend answers HTTP 200 with { status, message, data }: "1" ok, "0" refused (show the message), "2" error.
  • Request payloads are btoa(encodeURI(JSON.stringify(data))). That is an encoding, not encryption.
  • For a student, childUserId must be null, never 0.

Menu

  • The menu is rows in the database (MODULES + USER_RIGHTS), read through POST /api/v1/module-details. utils/dashboardNav.js maps it and applyStudentNavRules() hides or renames items the way the legacy sidebar did.
  • Icons are chosen from the label in iconForLabel(); the unread badge on Communication comes from components/student/inbox/InboxBadge.jsx, used by both K5NavRail.jsx and Sidebar.jsx.

Dummy student

Each page's hook has two sources with the same methods: the live one (services) and a sample one from utils/dummy*.js. Actions in dummy mode work in memory and reset on reload. A new page should follow the same split. My Profile does not (see D6 in the queue).

Decisions already made — do not reopen without asking

  • Student only, English only for now. No theme picker, Print, header bell or AI help.
  • No "Check before sending" dialog; its two warnings show above Send.
  • Date presets are 7, 30 (default), 90 days and This year. No "All time" (the backend caps a range at 366 days).
  • Mark as unread and attachment sizes are left out because the backend has neither.
  • The email body is fetched as text by the page and shown in a sandboxed frame through srcdoc. Do not change it to a frame src: only page requests carry the tab's X-Account header, so a frame address would load the wrong account or none.
  • The attachment route follows the backend's redirect itself and only to trusted storage hosts (amazonaws.com by default; override with INBOX_ATTACHMENT_HOSTS). The storage address is never given to the browser.
  • The star call's channel value is case-sensitive on the backend.

Backend follow-ups logged, not built

  • A mark-as-unread endpoint; attachment size in the list; an access check on announcement attachments.
  • Inbox date filters are read as India days on the backend, while the page uses the user's zone. Accepted for now.

11. Gotchas

  • A native <dialog> opened with showModal() ignores autoFocus on a field. Focus the field in the effect right after showModal() (see K5InboxCompose.jsx).
  • Text from announcements and previews can contain HTML entities; pass it through plainText() from utils/inbox.js before showing it.
  • "Mark all as read" covers all time, while the unread count shown covers the last 30 days. Do not disable the button from that count.
  • Local 404s on /api/v1/* usually mean the dev server was started before a rewrite changed, or the backend is down. Restart npm run dev before looking for a code fault.
  • next dev rewrites the Next.js block at the top of AGENTS.md; commit it with your work, do not fight it.
  • Other people keep stashes in this working tree. Avoid git stash here; a pop once failed part-way with new files in place.
  • The backend restarts and signs the user out on any Java class change during local work.
