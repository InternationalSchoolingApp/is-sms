A. Read first

This is the whole student dashboard in one page: what exists, which student sees what (learning program, grade, school, settings) and what to check. Every test case has a result box; your results are kept in this browser only (use Export to share them).

What the dashboard is

  • One URL for every student: /{school}/student. What changes is the look (decided by grade) and the content/conditions (decided by learning program, school, settings and the student's data).
  • Three new looks share the same components: Elementary (K-5, "Playful"), Middle (6-8, "Balanced"), High (9-12, "Mature"). A student for whom the new look is off sees the older standard shell.
  • Modules were migrated from the legacy Java pages; the legacy page is the reference for behaviour. Looks follow the mockups in D:\Workspace\K-5 dashboard, Grade 6-8 Dashboard and Grade 9-12 Dashboard (each has the same 18 pages).

Demo (dummy) URLs - no real data needed

Add these to any module URL after logging in: ?dummyStudent=Y&dummyGrade=K (or 1 to 12). Examples: /{school}/student/student-transcript?dummyStudent=Y&dummyGrade=10. Login note. Student login goes through the Java app (port 8080) and returns to the Next.js app (port 3000). If the Java backend is down you cannot sign in at all.

C. How to test - recommended order

Short answer: by learning program first for the logic, then by grade for the look. The conditions (what appears) depend on program, school and data; the look (how it appears) depends only on the grade band. Testing every look for every program would repeat the same checks, so split it:

  1. Wave 1 - smoke per look (3 students). Elementary, Middle, High: log in, open every menu item once, check no error page, the right look and the shell items (section 1).
  2. Wave 2 - program conditions (section B2). One BATCH, one Self-Study, one One-to-One student: check only the rows of B2 that differ (menu items, home wording, batch classes, training popup, setup page).
  3. Wave 3 - modules, once per look. Sections 2-13: run each case in all looks marked E M H. Use dummy URLs to switch looks quickly (dummyGrade=3 / 6 / 10), then repeat the "Needs data" cases with real students.
  4. Wave 4 - popups and gates (Popups section) with students that have the special data.
  5. Wave 5 - onboarding (later). Needs students that still have onboarding steps.
  6. Wave 6 - re-enrollment (phase3 branch). After the project owner merges phase4 into phase3.
Phone width: re-run Wave 1 once at about 375 px wide for each look.
