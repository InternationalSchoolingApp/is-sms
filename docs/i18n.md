# Student dashboard translations (i18n)

The student dashboard (everything under `app/[school]/(dashboard)`, including the Grade K–5 shell and the
onboarding pages) can be shown in **English (en), French (fr), Portuguese (pt, Brazilian), Chinese (zh, Simplified)
and Spanish (es)**. Enrollment and every other part of the app stay English.

Library: [`next-intl`](https://next-intl.dev) 4.x, used **without i18n routing**.

## How it works

| Piece | File |
|---|---|
| Languages, cookie name, BCP 47 tags, `normalizeLocale()` | `i18n/config.js` |
| Per-request locale + messages (cookie `NEXT_LOCALE`, default `en`) | `i18n/request.js` (wired by `createNextIntlPlugin` in `next.config.mjs`) |
| Loads a language's messages with English merged underneath | `i18n/loadMessages.js` |
| Server action that stores the choice | `i18n/actions.js` → `setUserLocale(locale)` |
| Dashboard provider (student's language) | `app/[school]/(dashboard)/layout.jsx` |
| Root provider (English, only `common` + `shared`) | `app/layout.js` |
| Language picker (top-right of every dashboard header) | `components/i18n/LanguageSwitcher.jsx` |
| Saved preference on SMS (other devices follow) | `services/languagePreferenceApi.js`, `components/i18n/LocaleSync.jsx` |
| Backend label helper | `i18n/labels.js` → `useLabelTranslator(ns)`, `labelKey(raw)` |
| Date helpers | `i18n/dateLocale.js` → `useDateFnsLocale()`, `useLocaleTag()`, `dateFnsLocaleFor(locale)` |
| Checker | `npm run verify:i18n` (`scripts/verifyI18n.mjs`) |

The URL never carries the locale: `proxy.js` and the backend rewrites read path segments, so a `/fr/...` prefix
would break them, and the dashboard is behind login (no SEO). Switching language sets the cookie and calls
`router.refresh()`: the dashboard layout re-renders with the new messages and all client state (React Query cache,
open panels) is kept.

## Message files

`messages/<locale>/<namespace>.json`, one file per namespace, the same files in all five languages, all listed in
`messages/<locale>/index.js`. English is the source of truth; `loadMessages` merges English under every other
language, so a missing translation shows English, never a raw key.

- `common` — generic words shared by every module (`common.actions.close`, `common.status.loading`,
  `common.table.showingEntries`, ...). Reuse it before adding a new key.
- `shared` — strings of components that are **also rendered outside the dashboard** (enrollment dialogs, payment
  modals, `components/ui`). Outside the dashboard they are English automatically (root provider).
- Every other namespace belongs to one area (`fees`, `inbox`, `k5Booking`, ...).

Keys: camelCase, grouped by component or section (`fees.table.dueDate`, `inbox.compose.subjectPlaceholder`).
No dots inside a key name.

## Writing translatable code

```jsx
"use client";
import { useTranslations } from "next-intl";

export function FeeDetails() {
  const t = useTranslations("fees");
  const tc = useTranslations("common");
  return (
    <>
      <h1>{t("title")}</h1>
      <p>{t("installmentsLeft", { count })}</p>          {/* ICU plural, see below */}
      <button aria-label={tc("actions.close")}>×</button>
    </>
  );
}
```

- **All user-visible text**: JSX text, `placeholder`, `title`, `aria-label`, `alt` (non-empty ones), toasts,
  confirm-dialog text, validation messages, empty states, `document.title`, chart labels/legends/tooltips.
- **Variables**: `"Hello {name}"` → `t("hello", { name })`. Never build sentences by concatenating translated
  pieces — word order differs between languages; put the whole sentence in one message.
- **Plurals**: `"{count, plural, one {# class} other {# classes}}"`. Chinese uses only `other`.
- **Markup inside a sentence**: `t.rich("terms", { b: (c) => <b>{c}</b>, link: (c) => <a href={url}>{c}</a> })`
  with `"Read the <link>terms</link>"`.
- **Hooks** can call `useTranslations` themselves (toast texts in `hooks/*`).
- **Plain functions / constants** (`utils/*`, `constant/*`) cannot use hooks: keep returning a *key* (or a stable
  code) and translate where it is rendered, or take a `t` argument. Do not translate at module level.
- **Never translate values used in logic**: things compared in `if`s, sent to the API, used as React keys, route
  segments, analytics event names, CSS classes, cookie/localStorage values. When a select's option label is also its
  value, split it into `{ value, label: t(...) }` and keep sending `value`.
- Don't change layout, styling, behaviour or API calls while extracting text.

## Dynamic content (from the backend)

| Kind | What to do |
|---|---|
| Finite labels the backend sends (menu module names, statuses like "Paid"/"Pending", day names, attendance states, club names) | `const tl = useLabelTranslator("menu")` → `tl(item.label)`: looks up `menu.<labelKey(raw)>`, falls back to the raw text. Add the keys you know (`"Fee Details"` → `fee_details`). Translate **at render**, keep the raw value in data and logic. |
| Free text written by people (inbox messages, news, announcements, diary, teacher comments, course/subject names typed by staff, backend error `message`s) | Show as-is. Out of scope (decided 2026-11-19). |
| Dates | Keep the existing date-fns / date-fns-tz pipeline and time zone logic, only add the locale: `format(d, pattern, { locale: useDateFnsLocale() })`. For `toLocaleDateString` / `Intl.DateTimeFormat` use `useLocaleTag()` instead of a hard-coded `"en-US"`. Don't change patterns. |
| Numbers / money | Unchanged (fee amounts must look the same as on invoices and payment pages). |
| Official documents (transcript, progress-report PDFs, certificates) | English (generated by the backend). |

Time zones are unaffected by the language. `INTL_TIME_ZONE` (`Asia/Singapore`, the project fallback) only
satisfies next-intl; don't use next-intl's `useFormatter` for dates.

## Translations

Write natural, school-appropriate UI text (students and parents read it; K–5 strings are for young children — keep
them simple and warm). French/Spanish/Portuguese: informal "tu" for K–5 screens, the polite/neutral form elsewhere
(fr "vous", es "tú" is fine for students, pt "você"). Portuguese is Brazilian, Chinese is Simplified. Keep brand
and product names (International Schooling, LMS, Pico, STEM) untranslated. Translations are ~30% longer than
English: if a label sits in a fixed-width spot that already truncates, leave it — do not redesign.
